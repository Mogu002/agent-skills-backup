# 清洗操作手册

本文件给出**分输入类型的清洗步骤**和**忠实性自检**。目标形态见 [`format-standard.md`](format-standard.md)。

原则：能交给脚本的机械转换就别手工做；只有需要语义判断（层级、噪声边界）的部分才由 Agent 处理。

## 第 0 步：识别输入类型

先判断来源属于哪类，决定清洗重点：

- **飞书 / Lark 导出 md**：混杂 CCM 私有 HTML（`<table>`、`<cite>`、`<callout>`、`<figure>`、`<bitable>`、`<grid>` 等）。→ 脚本主战场。
- **网页正文（HTML 或复制文本）**：噪声多在外壳（导航、推荐、footer）；结构标签相对标准。→ 脚本处理标签 + Agent 剔壳。
- **已是 Markdown**：可能只有层级混乱或轻微残留。→ 脚本轻扫 + Agent 修层级。
- **纯文本**：无结构。→ 脚本作用有限，Agent 按语义补层级（保守，不臆造）。

## 第 1 步：确定性 pass（执行脚本）

单文件：

```bash
python3 scripts/normalize.py <input.md> <output.md>
```

省略输出则打到 stdout；目录批处理：

```bash
python3 scripts/normalize.py <input_dir> <output_dir>
```

脚本负责：`<title>`→H1、HTML 表格→GFM/标签化 bullet（含 rowspan/colspan 展开）、`<callout>`→引用、`<cite>`→《标题》/@姓名、嵌入对象→占位、`<img>`→标准图片或占位、列表/加粗/换行/引用转换、空行折叠、行尾清理。

> 脚本只做**标签级**转换，不懂“哪一段是导航噪声”“这个粗体行该不该升成标题”——那是下一步。

## 第 2 步：结构 pass（Agent 判断）

对照 `format-standard.md` 逐项处理脚本管不了的语义问题：

1. **唯一 H1**：确认只有一个一级标题；多余 H1 按主题下沉。
2. **伪标题升级**：独占一行、领起段落的纯粗体短语 / 中文枚举章节标题 → 升为真标题；行内粗体前缀保持不动。
3. **层级校正**：消除跳级，保证 `#/##/###` 连续。
4. **剔壳**：删除面包屑、登录/cookie 横幅、相关推荐、重复页眉页脚等非内容外壳。边界不清 → 保留并标记。
5. **收尾**：确认无残留 HTML、无 `****` 空标记、无编造 URL。

## 第 3 步：忠实性自检（交付前必过）

逐条确认，任一不满足就回退修正：

- [ ] **内容零丢失**：实质文本、数字、数据、日期、引用、链接都还在，没有被摘要或删节。
- [ ] **顺序未改**：没有按“重要性”重排原文段落顺序。
- [ ] **无注入**：没有加入原文没有的结论、推断、评价或过渡句。
- [ ] **删除可解释**：每一处删除都能归为“非内容外壳”，并已在报告列出。
- [ ] **图片诚实**：没有为无 URL 的图片编造链接。
- [ ] **正文纯净**：没有混入 frontmatter、`source_id`、元数据或本 skill 的批注。
- [ ] **幂等**：再跑一次 `normalize.py`，输出不变。

## 第 4 步：产出元数据（写在报告，不写进正文）

给下游 `llmwiki add` 建议以下值，并标注“建议，非既成事实”：

- `title`：文档完整标题（取自 H1 或来源；缺失时给中性具体标题）。
- `date`：来源发布/事件日期，`YYYY-MM-DD`；无法确定就说明“未知，交由 add 用导入日期”。
- `url`：来源原始链接（若有）。
- `collection`：按来源渠道建议 1-2 层，如 `web`、`lark/policies`；**不按主题分类**（主题属于 wiki 的 tags/概念页）。

示例交接提示（供用户参考，本 skill 不执行）：

```bash
python3 scripts/llmwiki.py add <output.md> \
  --title "<建议标题>" \
  --url "<来源URL>" \
  --collection "<建议collection>" \
  --date "<YYYY-MM-DD 或省略>"
```

## 常见坑

- 飞书表格里嵌套列表/图片时，别硬塞进 GFM 单元格——脚本会转成标签化 bullet 块，保留即可，不要再手工压回表格。
- `<cite type="user">` 会转成 `@姓名`；`doc/wiki/bitable` 引用转成《标题》。这是可读化，不是丢信息，保持原样。
- 网页复制文本常把侧栏、目录、推荐混进正文中段，不只在头尾；剔壳时通读全文，别只切首尾。
- “更新记录 / 版本表”是内容，不是噪声，务必保留。
- 纯文本补层级要保守：只在语义明确时升标题，宁可欠一级也不要臆造结构。
