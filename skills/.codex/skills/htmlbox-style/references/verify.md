# 验收流程（截图 + console，缺一不可）

静态渲染检查工具（如 `html_vision`）能一次给出"有没有渲染、字有没有被切、console 有没有报错"。它返回的是自然语言结论，**必须逐条读**，不是只看有没有 "no issue"。

## 1 调用方式

```bash
python3 html_vision.py - <<'EOF'
{"task":"检查图表：1) 是否空图/报错/长时间加载中；2) 标签是否被裁切、压线、重叠；3) 数值与标题是否一致（写明具体数字）；4) 浅底上的文字对比度是否可读；5) 是否有异常留白。给出 no issue 或具体问题。",
 "url":"file:///absolute/path/to/x.html"}
EOF
```

要点：
- `url` 必须是绝对路径的 `file://`，不要起本地服务器。
- `task` 里把**期望数字**写进去（"A 158 / B 176"），否则模型只能用"大致符合"糊过去。
- 批量时每 6 个一批，别一次 32 个，结论会互相污染。

## 2 验收清单（逐条打勾）

- [ ] 无 console error（`Uncaught`、`option` 非法、资源 404）
- [ ] 不存在 "图表渲染失败" / 空画布 / "加载中"
- [ ] 所有数值标签完整可见，没有被容器边或相邻标签切掉
- [ ] 图例不压数据、不压标题
- [ ] 轴名、单位、刻度齐全且与数据量级匹配
- [ ] 标题里的数字能在图里找到出处
- [ ] 浅底上的文字是深色（或已加粗加深）
- [ ] 时间/分类标签没有互相覆盖
- [ ] 与同批其他图的风格一致（字号、色系、留白）

## 3 常见结论怎么处理

| 工具结论 | 判定 | 动作 |
|---|---|---|
| `no issue` | 通过 | 记录，进入下一批 |
| "标签裁切 / 贴边" | 真问题 | 加 `grid.right` / 缩小字号 / 改 `label.position` |
| "对比度不足" | 真问题 | 换深色字或加深底色 |
| "下方大面积留白" | 多半是画布高度与内容不匹配 | 调 `#chart` 高度；页面级留白可忽略 |
| "数值与标题不一致" | 必须核实 | 可能是工具误读，也可能是真错；用源数据算一遍再决定 |
| "面积/比例不符" | 必须核实 | 工具按**视觉高度**猜面积，容易把不同宽度的块误判；用像素测量或公式复核后再改 |

最后一条尤其重要：本项目里两次「面积不符」的报告，实际是工具把"等高但不等宽"的块误读成"面积相等"。**人工复核优先于工具结论**，但复核完要在记录里写清"为什么判定为误报"。

## 4 批量回归

改完一轮后，至少重跑：
1. 被改过的图（必跑）；
2. 与它共用同一段模板代码的图（例如改过 `base.py` 的骨架，就全量跑一遍）。

产物落到 `assets/html/`，命名与图表 id 一致，便于文档引用与回归比对。
