# Base Site 风格手册

本文汇总业务系统、数据、后端与前端的稳定设计原则。具体平台命令见 [Skill 主流程](../SKILL.md)，具体 ABI 见 [代码开发手册](development.md)。

## 业务与数据设计

1. 先明确用户、目标、核心流程、状态变化和失败路径，再设计表与页面。
2. 具有独立生命周期、权限或统计需求的业务事实使用独立表，并明确数据所有权、归档和追溯要求。
3. 每张表有可读主字段、稳定业务标识、状态、负责人、时间和必要关系。
4. 状态使用受控单选并定义合法转换；关系、金额、日期、人员使用对应 Base 字段。
5. 页面围绕用户任务组织，不按表机械生成 CRUD。
6. 每个 operation 定义固定输入、输出、权限、失败语义和影响范围。

信息不完整时推导最小、自洽的设计，并在交付中说明关键假设。只有数据所有权、权限、安全或核心流程存在实质歧义时才询问用户。

## 数据链路

- Base 是业务事实源，不在 Page 或 FaaS 维护同一份主数据。
- 读取优先使用 SQL Function；搜索、筛选、分页、关联和聚合下推到 SQL。
- SQL Function 按一次用户操作同步需要的数据包划分，不按表或页面区块机械拆分；前一个 SQL 只为后一个 SQL 提供关联 ID 时优先合并。
- SQL 能完成的计算不放进 FaaS，也不拉全表到 Page 再计算；避免整表读取和 N+1 查询。
- 创建、更新、删除、权限校验和状态转换使用 FaaS。
- FaaS 需要读取时复用固定 SQL Function；页面和 FaaS 不使用 Base records 读 OpenAPI。
- 公式和 lookup 只承载需要长期显示在 Base 中的派生结果，避免重复保存易漂移数据。

## FaaS 一致性与调用链

- 每个写入 operation 先定义成功条件、一致性要求、是否允许部分成功和失败后的重试边界，再选择实现方式。
- 实现前列出远程调用及依赖；无依赖的 SQL、用户信息等无副作用读取先同时启动，在共同消费结果的位置汇合。
- 使用满足业务语义的最短远程调用链。写前查询、写后回读和补偿请求只有在能够降低明确且不可接受的业务风险时才加入。
- 同一张表的多条操作优先使用批量接口；不同表或不同请求之间没有数据依赖时并发执行，只有后一步依赖前一步结果时才串行。
- 允许弱一致性时，可以复用页面已经取得的非安全敏感状态；身份、权限、租户隔离和其他关键约束必须由服务端可信数据确认。
- Base 不具备事务、唯一约束或原子条件更新能力时，不用“先查再写”、失败回滚等多次请求模拟强一致性；业务依赖这些能力时记录为不支持或改用具备相应原语的存储。
- 多路写入必须区分全部成功、部分成功和全部失败。未知结果或非幂等创建不自动整体重试，避免产生重复记录。

## 后端与安全

- 一个 FaaS Function 对应一个明确业务动作；输入从 `unknown` 校验。
- Site token、table ID、字段名、origin、method、project ID 和 function ID 固定在代码中。
- 按 operation 契约校验身份、权限、字段、状态转换和批量数量；只有底层存在可靠幂等原语时才承诺严格幂等，失败返回稳定业务码与可读信息。
- 当前访问者的查询权限使用 SQL `CURRENT_USER_ID()`，不相信页面传入的用户 ID。
- 不记录或返回 token、secret、cookie 和不必要的敏感数据。
- 修改现有系统时保留需求外 operation、包管理器、锁文件和目录结构。

## 前端工程

- 按业务能力组织页面、组件和 operation；组件不同时承担路由、请求、表单和复杂展示。
- 修改现有页面时保留框架、包管理器、锁文件、路径别名和 CSS 体系。
- 只引入解决当前问题的依赖；简单格式化、日期转换或局部状态不增加重型库。
- 导航、标题、筛选、主要操作和内容容器优先渲染；远端区域分别处理 loading、empty、error、forbidden 和 success。
- 互不依赖的请求并行；详情、历史、弹窗和非当前 tab 按需加载。
- 搜索防抖并取消过时请求；旧响应不能覆盖新筛选状态。
- 写入期间禁用重复提交；成功后只刷新受影响的列表、指标或详情。
- 轮询设置停止条件、最大时长和卸载清理。

### React

- 可从 props/state 推导的值不放进 Effect 或重复 state；用户动作由事件处理器触发。
- 状态放在最接近使用的位置；列表使用稳定业务 ID。
- 确认性能瓶颈后再使用 `memo`、`useMemo` 或 `useCallback`。
- 大列表使用服务端分页、窗口化或分段渲染；低频重型功能按需加载。

### 资源、性能与安全

- 保持 Vite 相对路径部署配置；production build 关闭 source map。
- 非首屏图片懒加载并声明尺寸；字体只加载实际字重和字符集；第三方脚本不进入首屏。
- 公开制品不包含凭证、调试信息、`node_modules` 或嵌套 `dist`。
- 脱敏真实响应可作为布局 fixture，但不能替代用户对 Preview 的体验。

## 可访问性与交互状态

- 使用语义化 HTML；表单有可感知 label，图标按钮有 accessible name，错误提示关联对应字段。
- 核心任务支持键盘和清晰焦点；弹窗管理焦点进入、陷阱和关闭恢复。
- 颜色不是唯一状态信号；正文和控件保持可读对比度，点击目标适合触屏。
- 窄屏下主要列表、表单和操作可到达；尊重 `prefers-reduced-motion`。
- loading、空、部分数据、错误、无权限和成功都有明确 UI。

## 验收质量

- Preview 的 production build、SQL 编译校验和发布状态由 `base-site deploy` 统一完成。
- 检查核心 operation 中连续出现的远程 `await`：后一个调用必须真实依赖前一个响应；仅用于取得关联 ID 的串行 SQL 优先合并，输入已确定的无副作用请求必须并发。
- 记录首屏和核心交互的远程往返次数；每增加一次调用都应有按需加载、权限/失败隔离、结果规模或平台能力方面的明确理由。
- 页面无 starter 文案、无效按钮、伪成功状态和未使用依赖。
- 发布 Preview 后交付真实 Site URL、Base URL 和体验路径并停止，由用户在飞书登录态下体验。
