# 抖音收藏整理

依赖可控制用户已登录会话的 ego-browser；先读取可用的 ego-browser Skill 并执行 `ego-browser skill`。如果没有可用登录态，交还浏览器让用户登录，不导出 Cookie。用户指定浏览器操作时直接遵循；不要安装无关采集器或转写工具。

## 默认流程

1. 在一个 TaskSpace 中打开用户提供的收藏页。记录账号和用户授权范围；整个任务复用该空间，暂停或失控时按浏览器指南交还控制。
2. 读取现有收藏夹及其作品 ID 集合，写入任务工作目录作为基线。若只整理默认/未分类收藏，“视频”标签不是默认收藏夹，它包含已归类作品。将全部收藏 ID 减去基线全部收藏夹 ID，才得到待整理集合。原有收藏夹不删、不改名、不移出作品。
3. 滚动读取到页面明确显示没有更多；没有更多标志缺失时只能报告部分采集。元数据计数可能包括已下架作品，不能为凑齐数字改动其他条目。按 ID 去重。分页读取、分类方案和已完成记录分别持久化，恢复时核对实际状态。
4. 根据标题、作者、标签和必要的封面/正文定类。渲染数据中的 `videoTag[].tagName` 可辅助识别空标题作品；“生活记录/随拍”等宽泛标签不能当作精确主题证据。少量歧义条目可汇总封面做视觉核对，必要时结合站内相关主题词或打开作品；不要仅凭作者名猜空标题。先用现有分类；主题不合适时新建。规则匹配只生成候选分类，处理含义歧义和广告标签污染后再提交。内容不足时查看作品，仍不确定则保留待核对，不能声称已准确分类。
5. 先跑通一小批：进入“视频 → 批量管理”，勾选限定 ID，核对已选数量，选择“加入收藏夹”，只选一个目标，再确定。原有公开收藏夹不能因批量新增而公开原本私密的收藏；未授权公开时为这些新增条目另建私密夹。新建时读取“设置为公开”开关；未授权公开则明确关闭，并在提交前核验 `aria-checked=false`。创建后可能自动勾选新夹。
6. 核验目标夹确实包含这批 ID，并记录 `{id, category, verified}`。复用成功路径分批处理，提交前检查本批 ID 全部属于未分类集合、无已完成 ID、无基线原有作品。失败先观察状态，不盲目重发。
7. 汇总各分类新增数量。复查基线原有 ID 仍在原收藏夹、所有已归档 ID 出现在目标夹。总收藏不能因分类操作减少。报告成功、待确认、无法显示的范围，并依照 ego-browser 指南 finish。

## 页面操作经验

- 收藏夹侧栏和目标收藏夹选择窗口均按需分页；分别滚动各自内部容器。目标选择窗口按页加载（观察值为每页 20 个）。找不到名称时先滚动窗口内部列表直到条目数停止增长，再决定新建；不能把首屏或首批 20 行当作全部收藏夹。同名夹必须用已观察的 ID/基线身份区分，不可取第一个提交。

- 截图/快照先观察，再使用实际出现的文案、属性和选择器。类名可能变化，失效时重新取证，不写死账号、收藏夹 ID、空间 ID 或请求签名。
- Semi UI 的 checkbox 输入可能被展示层遮挡。点击其可见 `.semi-checkbox` 容器；直接 `input.click()` 可能不改变应用状态。批量动作必须核对 UI 已选数。
- 不同操作的选择弹窗也可能同时留在 DOM，必须按标题和可见性锁定正在操作的窗口，再在该窗口内枚举/滚动目标行。提交后弹窗可能只是隐藏，DOM 仍存在；等待可见状态消失或“批量管理”恢复，不用“节点不存在”判断成功。
- 收藏夹“...”菜单可能需要先 hover 当前行；编辑新建收藏夹可纠正隐私设置，但不要改动基线原有夹。
- 页面列表可能保留隐藏弹窗内容；提取和勾选都限定 `.route-scroll-container` 中目标列表，不能读取隐藏选择器造成串表。
- 普通 DOM 读取不足时，可用 `scripts/browser-state.mjs` 的 `readState` 读取渲染列表的 React 元数据。优先读取列表宿主节点 `__reactProps` 中已提交的 children；DOM 节点挂载的 Fiber 及 alternate 可能滞后，不能单凭旧 Fiber 的数组长度判断加载进度。它是条件兼容辅助，依赖运行页面结构，失败后退回 DOM/快照；不能把结果为空解释为用户没有收藏。
- 如采用脚本批量点击，按浏览器当前已观察结构操作可见列表中的勾选容器，每次等待并检查状态；不得调用未知写接口或自行构造签名。

## 已验证的批量辅助

在页面结构与脚本契约一致时，使用 `scripts/organize-batch.mjs` 导出的 `organizeBatch(page, category, ids)`。它复用已加载列表对象和已观察到的 `changeSelectedItems` 页面选择状态方法，核对 UI 已选 ID/数量，再通过正常“加入收藏夹/确定”界面提交。没有构造网站写接口。先读函数实现；每批不超过页面 `maxSelectedCount`（“视频”管理观察值为 100，“收藏夹内移动”观察值为 50，运行时仍检查）。辅助函数默认拒绝公开目标夹；仅用户明确授权公开时才传 `allowPublic: true`。调用时通过 `knownFolderNames` 传入基线及已完成记录中的已有名称；已知名称未加载出来时函数会拒绝重复创建。调用前由任务级程序检查基线保护集、去重和已完成集；调用后保存结果并最终实读核验。页面结构不匹配时停止使用该辅助，回到可见 UI 取证；不要猜新的状态函数。

读取分页时优先 `readProgress()` 获取小体积进度，每个分页循环结束才用 `readState()` 取得元数据；不要每次滚动跨进程传回整份收藏。

在已观察到列表实例提供 `getDataList/getHasMore/getStatusCode/loadMoreData` 时，辅助函数优先读取这个实例的实际列表状态。滚动没有触发下一页时，可用 `loadNextPage()` 触发该页面原有的加载动作，再等待数量或 hasMore 改变；它不构造接口请求。只在状态码为 0 且 hasMore 明确为 false 时判定读取完成。方法不存在或连续数次没有进展时，回到页面取证，不空转重试。

## 同名新夹的修复

只有当来源夹能够通过运行日志和 ID 证明是本轮新建，且全部内容属于本轮待整理集合时，才可清理它。逐批从该新夹用“移动到”合并至原有目标夹；每批读取实际最大选择数，确认目标身份和数量增量。核验来源夹为空、目标夹保留原有 ID 且包含全部新增 ID 后，删除这个新建空夹，并处理页面的“确认删除”提示。不要删除用户原有同名夹，不要使用“取消收藏”。

## 持续改进

每完成一个可复用小流程，再更新本 Skill 中对应步骤或辅助函数；只保留跨条目成立的约束。修改后复用到下一小批，检查真实结果，再扩大规模。个人收藏数据、分类草案、运行日志和凭据均留在任务目录，不放进 Skill。
