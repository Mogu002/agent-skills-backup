# Evaluation Cases

这些用例用于人工或新上下文回放。不要把本文件中的样例值当作生产默认值。

## 路由

| 输入 | 预期 |

| “根据录音、表单 schema 和模型填写结果，按字段识别/准确/完整/格式打分” | 触发 |
| “帮我质检这批语音自动填表结果，错的字段要写原因” | 触发 |

## 行为用例 A：完整通过

Schema：

- `所属機能モジュール`：单选，包含 `ワークベンチ`
- `体験上のペインポイントタグ`：多选，包含 `読み込みが遅い`、`操作が煩雑`
- `体験評価`：1 至 5 分
- `対応進捗`：进度

权威转写：

> 所属機能モジュールはワークベンチ。読み込みが遅く、操作も煩雑です。体験評価は 2、対応進捗は一割です。

模型结果：

- `所属機能モジュール`=`ワークベンチ`
- `体験上のペインポイントタグ`=`読み込みが遅い`、`操作が煩雑`
- `体験評価`=`2`
- `対応進捗`=`10%`

预期：四个维度均通过。

## 行为用例 B：更正、追加与格式错误

Schema：

- `対象プラン`：单选，仅包含 `無料版`、`プロフェッショナル版`
- `タグ`：多选，包含 `遅い`、`煩雑`、`不正確`
- `提出日`：日期 `yyyy-MM-dd`

评测基准日期：`2026-08-03`

权威转写：

> 対象は無料版、いやプロフェッショナル版です。タグは遅いと煩雑、それから不正確も追加。提出日は明日です。

模型结果：

- `対象プラン`=`無料版`
- `タグ`=`遅い`、`煩雑`
- `提出日`=`明日`

预期：

- 字段识别：通过，内容均进入对应字段。
- 内容准确：不通过，`対象プラン` 未采用更正后的最终值。
- 信息理解完整性：不通过，`タグ` 遗漏追加项，且更正关系处理错误。
- 类型与格式：不通过，`提出日` 未转换为 `2026-08-04`。

## 行为用例 C：只有参考答案

输入只有参考答案和表单链接；分享页为空，底层数据表也没有可唯一定位的提交记录，并且没有语音或权威转写。

预期：状态为“待确认”；明确缺少事实源和待评测结果，不输出四维通过/不通过。

## 行为用例 D：可见表单为空但底表已有结果

表单分享页的输入控件全部为空，但通过分享链接可解析到底层 Base；字段集合能唯一定位到一张表，且该表只有一条提交记录。

预期：读取该底表记录作为模型结果，不把空白分享页误判为“没有填写结果”。

## 行为用例 E：隐藏字段存在于底表

可见表单包含 16 个问题，参考答案额外包含 `フォローアップ責任者`；该字段未加入分享表单，但存在于底层数据表 schema 和提交记录中。

预期：把该字段纳入评测，不进入 schema 冲突状态。

## 行为用例 F：人员别名

原始语音中的人员名与表单显示名不同，但已有独立证据确认二者指向同一账号。

预期：该人员字段可按等价值处理；若没有身份映射证据，则进入“待确认”。

## 行为用例 G：关联项无法唯一匹配

原始语音只提供简称，候选数据中有两条同名记录，因此无法唯一匹配；模型保持关联字段为空。

预期：该字段处理正确。若评测输入未提供候选数据，无法确认是否真的存在歧义，则状态为“待确认”。

## 行为用例 H：多条提交记录

表单链接能定位到底层数据表，但表内有多条提交记录，用户未提供 `record_id`、提交时间或业务唯一键。

预期：状态为“待确认”；列出可用于定位的字段，不默认取最新记录。
