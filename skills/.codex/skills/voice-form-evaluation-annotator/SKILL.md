# Voice Form Evaluation Annotator

评测语音驱动的表单填写结果。以用户原始表达为事实源，参考答案只用于辅助定位，不代替原始语音或权威转写。

## 最小输入

开始打分前取得：

1. 原始语音或权威转写。
2. 表单分享链接或目标表单 schema：字段名、字段类型、选项、日期格式及必要的关联约束。
3. 模型实际写入的字段和值。这些值可能只存在于用户当前 Chrome 标签页的未提交表单状态，也可能已写入底层提交记录。必须读取与本次评测对应的实际状态；重新打开链接后出现的空白表单不属于模型输出。
4. 解释相对日期所需的评测基准日期和时区；出现“我”时还需当前用户身份。
5. 可选的参考答案。

证据优先级为：原始语音或权威转写 > 表单 schema 与运行上下文 > 模型实际写入值 > 参考答案。参考答案与语音冲突时按语音评测，并单独指出参考答案冲突。

## 评测门槛

以下任一情况存在时，输出“待确认”及缺失或冲突项，不给四个维度硬打分：

- 缺少原始语音和权威转写。
- 无法观察模型实际写入值。
- 表单、模型输出和参考答案的字段集合明显不属于同一任务。
- 参考答案包含可见表单和底层数据表 schema 中都不存在的实质字段，且无法确认该字段是否自动生成或不适用。
- 底层数据表存在多条提交记录，但没有 `record_id`、提交时间或业务唯一键来定位待评测记录。
- 相对日期缺少基准日期、人员指代缺少身份上下文，或缺少候选数据而无法判断人员/关联记录是否可唯一匹配。
- 关键语音内容含混，无法可靠确认用户原意。

“待确认”是前置状态，不是第五个评分结果。证据齐全后，每个维度只能为“通过”或“不通过”。

## 默认流程

1. **取证**：读取语音或转写、完整 schema 和模型实际结果。若用户已在 Chrome 中打开填写后的表单，优先复用该现有标签页读取当前未提交状态；若结果已提交，则用可唯一定位的底层记录取证。全程只读，不刷新、填写、清空或提交表单。
2. **对齐**：按稳定字段 ID 对齐；没有 ID 时按精确字段名对齐。建立字段清单：`字段 | 类型/约束 | 用户最终表达 | 模型值 | 参考值 | 证据位置`。
3. **解析最终意图**：处理更正、追加、否定、覆盖和指代。区分应写入字段与应保持为空的字段；已确认无法唯一匹配的人员或关联项应保持为空，不把未表达或无法确定的内容补成默认值。
4. **检查门槛**：先处理缺证据、跨任务字段和 schema 冲突。未通过门槛时停止，不猜测。
5. **独立判定四维**：按 [scoring-rubric.md](references/scoring-rubric.md) 逐维检查。同一字段可在多个维度失败，不强行把问题只归到一个维度。
6. **输出证据**：任一维度不通过时，在“主要字段证据”中只列与正确值不一致或写错字段的项，每个字段使用一行编号格式：`字段名 识别为 模型值，答案为 正确值`。失败原因放在维度结果中，不在字段证据下再展开子项。

## Chrome 当前页取证

用户提供表单 URL，且说明已在 Chrome 中打开或页面上已有填写结果时，按以下方式读取：

1. 使用电脑控制的浏览器清单能力查看所有 Chrome 实例、配置和已打开标签页。不要默认第一个名为 `Chrome` 的浏览器就是用户所指的配置。
2. 在全部 Chrome 实例中匹配现有标签页。比较 URL 时使用实际 URL，将 Markdown 中的 `\&` 视为 `&`，忽略 fragment，并核对 origin、pathname 和查询参数。
3. 找到唯一匹配项后，用该页的 tab ID 和 browser ID 绑定现有标签页。不新建标签页，不调用 `goto`、`reload`、前进或后退，以免丢失客户端中尚未提交的填写状态。
4. 先读取页面的可访问性树或 DOM 快照；只在字段值、选中状态或评分无法识别时，再使用只读 DOM evaluate 或截图核对。不为了取证而展开下拉框、改变选中状态或触发语音输入。
5. 区分“已选值”和“候选项”。下拉选项文本出现在可访问性树中，不代表它已被选中；只有控件当前 value、已选 chip/list、`checked`/`aria-checked`、评分状态或等价的明确页面证据才可记为模型值。
6. 如有多个标签页匹配同一 URL，只在用户明指的配置、当前页或标题足以唯一定位时继续；否则输出“待确认”，不猜测哪个客户端状态是本次模型输出。

该现有标签页中明确可见的当前值，就是未提交场景下的“模型实际写入值”。与之相同的公开分享链接在新会话中显示为空表单，不能推翻这些已取得的页面证据。

## 飞书表单适配

用户提供飞书/Lark 表单分享链接时：

1. 若用户当前 Chrome 页面已有填写值，先按“Chrome 当前页取证”读取这些值，将其作为未提交的模型结果。
2. 解析分享链接并读取表单详情，取得 Base token、可见问题及其字段 ID。
3. 在该 Base 中定位字段集合覆盖这些问题字段的底层数据表。
4. 读取底层数据表的完整 schema。隐藏字段或未加入分享表单的字段也属于候选评测范围，不能只使用可见问题列表。
5. 只有能证明评测对象是已提交结果时才以底层记录作为模型结果。底表只有一条不足以证明它就是当前未提交页面对应的结果；已确认为提交场景且只有一条记录时可直接使用，有多条时必须用 `record_id`、提交时间或业务唯一键定位，不能默认取最新一条。
6. 表单分享页通常用于新建提交，同一 URL 在独立浏览器会话或重新打开后可能显示为空。不要用这个空白页面否定 Chrome 现有标签页或已唯一定位的底表记录中的结果。

无法访问底层 Base 时，只有分享页明确展示已有值才能继续；否则输出“待确认”并说明缺少可读取的提交记录。

## 四维判定

- **字段识别**：内容是否进入正确目标字段；不评价措辞是否自然。
- **内容准确**：写入值是否符合用户原意或属于明确等价表达。
- **信息理解完整性**：用户明确表达的信息是否保留，前后关系是否处理正确。
- **类型与格式**：结果是否符合字段类型、字段格式、已有选项和可提交要求。

一个维度中只要存在一个已确认失败字段，该维度即为“不通过”。只有该维度的所有适用字段都满足规则时才为“通过”。

## 输出格式

```markdown
## 评测结论
- 状态：已完成 | 待确认
- 事实源：语音 | 权威转写
- 表单/结果匹配：是 | 否 | 待确认

## 维度结果
| 维度 | 结果 | 未通过字段与原因 |
|---|---|---|
| 字段识别 | 通过/不通过 | ... |
| 内容准确 | 通过/不通过 | ... |
| 信息理解完整性 | 通过/不通过 | ... |
| 类型与格式 | 通过/不通过 | ... |

## 主要字段证据
1. `字段名` 识别为 `模型值`，答案为 `正确值`

## 待确认项
- 仅在状态为“待确认”时列出缺失证据、冲突字段和需要确认的问题。
```

四维全部通过时可写“完全通过”；否则只报告维度结果，不自行换算数值总分。

“主要字段证据”必须使用连续编号的单行列表，不使用嵌套项目符号。若要明确强调自由文本或人名来自语音识别，可将“识别为”写成“语音识别为”。这里的“答案”指按本技能证据优先级得出的正确值；参考答案与权威转写冲突时，仍按权威转写填写并另行说明冲突。

## 边界

- 人员显示名存在语言或别名差异时，只有能验证映射到同一人员才视为等价。
- “我”只可在人员字段中解析为当前用户；写入普通文本字段时保留原始文本含义。
- 参考答案中的字段不自动成为表单应有字段；先同时检查可见表单和底层数据表 schema。
- 不因参考答案省略某字段就断言该字段应为空，仍须回到原始语音。
- 不修改、清空或提交用户表单，不把评测动作变成数据写入。
