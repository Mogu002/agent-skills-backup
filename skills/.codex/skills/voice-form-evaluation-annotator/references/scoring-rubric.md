# Scoring Rubric

仅在 `SKILL.md` 的评测门槛通过后读取本文件。四个维度独立判定，每个维度只有“通过”和“不通过”。

## 1. 字段识别

评测问题：用户表达的内容是否写入正确字段，不判断表达是否合适。

**通过**

- 所有内容均写入对应目标字段。
- 已验证为同一人员的多语言显示名或别名可视为同一值。

**不通过**

- 任一关键内容写入错误字段。
- 字段发生明显错配。

备注必须指出哪个字段未正确写入，以及内容实际被写到了哪里或为何错配。

## 2. 内容准确

评测问题：写入的字段值是否符合用户原意。

**通过**

- 写入值与用户表达一致。
- 写入值属于明确等价表达，例如“七成”与 `70%`、“最高档”与量表最高分。
- 相对日期按已知评测基准日期正确换算。
- 可确定的口述邮箱被规范为合法邮箱地址。

**不通过**

- 值与用户原意不符。
- 肯定与否定、等级、对象、数值或项目被错误替换。
- 模型无依据补充了用户未表达的内容。

备注必须指出内容识别错误的字段、模型值和用户原意。

## 3. 信息理解完整性

评测问题：是否保留用户明确表达的信息，并正确处理信息之间的前后关系。

**通过**

- 用户明确提到的信息均被保留。
- 更正采用最终值，例如“选 A，不对，是 B”只保留 B。
- 追加合并完整，例如“选 A 和 B，再加 C”保留 A、B、C。
- 否定和覆盖关系处理正确。
- 人员字段中的“我”解析为已确认的当前用户。

**不通过**

- 遗漏任一明确表达的信息。
- 追加项缺失。
- 更正后仍保留被否定或被覆盖的旧值。
- 否定关系被反转。
- 人员字段中的“我”被直接写成文本“我”，或被解析为错误人员。

备注必须指出具体错误字段及遗漏或关系处理错误。

## 4. 类型与格式

评测问题：写入结果是否符合字段类型、字段格式和可提交要求。

### 日期

- 日期应正确转换为目标字段格式。
- 用户只提供日期、未提供时间，而字段需要时间时，写入当天 `00:00`。
- 相对日期必须基于已知评测基准日期换算。
- 用户提供具体时间时应保留该时间。

### 数字与货币

- 正确提取数值并完成明确单位换算，例如“三十万”写为 `300000`。
- 货币字段按目标字段币种存储数值；不做汇率换算。
- 数量、金额和评分写入数值，而不是混入无法提交的单位文本。

### 进度

- 数字表达或明确语义应转换为进度值，例如“七成”=`70%`、“一半”=`50%`、“全部完成”=`100%`。

### Email

- 邮箱必须完整且格式合法。
- 明确的口述形式可规范化，例如“账号 123456 的 QQ 邮箱”=`123456@qq.com`。

### 单选、多选与复选框

- 单选和多选只能写入 schema 中已有选项。
- 多选须完整保留所有最终选项。
- 复选框的勾选状态须与用户的肯定或否定一致；用户明确说“否”时，已有勾选也应取消。

### 其他字段

- 文本、人员、电话号码、条码、地理位置、群组、关联、NPS 等字段按表单 schema 和问卷约束检查。
- 不臆造文档未定义的格式转换。
- 已有候选数据足以证明人员或关联项无法唯一匹配时，正确结果是保持为空，不强行选择。
- 缺少候选数据或配置、无法判断是否可唯一匹配时进入“待确认”。

任一适用字段未满足以上格式即为“不通过”，并注明字段及违反的类型或格式约束。

## 交叉判定

- 四维不是互斥错误分类。同一字段既可能写错字段，也可能遗漏目标字段或违反类型。
- 不要用格式问题掩盖语义错误，也不要因为值格式合法就判内容准确。
- 对未表达字段，模型擅自填写属于内容准确问题；是否还构成完整性问题，依据其是否改变了用户最终意图独立判断。
