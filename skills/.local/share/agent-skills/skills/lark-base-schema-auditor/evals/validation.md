# 验证记录

## 模式与证据

主模式为 Codify，叠加轻量 Harden。

| 维度 | 依据与限制 |
| --- | --- |
| 知识 | `lark-base-reader` 的只读定位流程、`lark-base` 的字段读取规则和字段 JSON SSOT、当前 `lark-cli` help |
| 行为 | 用户给出的代表性首条记录已做真实只读回放；尚无多批历史成功/失败轨迹 |
| 验证 | 纯标准库单元测试、CLI 退出码测试、真实 Base 元数据回放、Skill Manager 导入预览 |
| 风险 | 流程只读，不修改 Base；主要风险是语义字段误配和不完整分页导致误判 |
| 路由 | 与 `lark-base-reader`、`lark-base` 的元数据读取、修改和记录分析意图相邻，已在 description 与评测集中分开 |

确定性部分进入 `scripts/audit_schema.py`：标准条目解析、Lark 字段类型规范化、一对一映射校验、缺失/多余/类型/选项差异和退出码。字段名翻译或同义关系仍由 Agent 判断；脚本不做模糊匹配，也不会根据字段顺序猜测。

## 已完成验证

- Python 3.9 标准库单测：8 项通过。
- `py_compile`：脚本和测试通过。
- JSON 与 diff 检查：评测集可解析，`git diff --check` 通过。
- Skill Manager 隔离环境导入与回读：名称、frontmatter 和完整 5 文件目录有效，预览 `issues` 为空。
- 真实只读回放：要求与实际字段均为 10 个；语义映射后 8 个匹配、2 个类型不符、0 个缺失、0 个多余。两个差异都由 `number/plain` 与专用数字样式要求不一致造成，证明脚本没有只比较顶层 `number`。
- 仓库回归：`npm test` 的 42 项测试通过，`npm run build` 通过。

真实回放只用于验证行为，没有把 Base URL、token、record ID、字段 ID 或用户数据写入 Skill 包。

## 路由与行为覆盖

`cases.json` 包含：

- 直接、间接、英文和信息不全但应先触发的正例。
- 修改表结构、记录值检查、纯对象定位和通用建模等负例或 hard negative。
- 视图首条记录、跨语言字段名、专用 number style、多表消歧、选项开关、未知类型、认证失败和审计后修复等行为场景。

这些案例完成了人工一致性检查，未做独立模型多轮路由评测；不能据此声称自动触发在所有模型上稳定。

## 假设与剩余风险

- 检查标准采用逐行 `字段名（字段类型）` 或 `字段名 (字段类型)` 格式；其他自然语言 schema 需要先转换或停止。
- 脚本支持当前字段 JSON 中的 `type`、`style.type`、`multiple` 和 `bidirectional` 语义。Lark CLI 返回结构或字段类型新增时需要更新映射和回归测试。
- 语义字段映射可能存在业务歧义。Skill 要求仅映射唯一明确的翻译/同义字段，否则报告未匹配并询问用户。
- `--check-options` 是规范化后的精确集合比较，不处理跨语言选项翻译。
- 字段列表超过单页时由执行 Agent 按 Lark CLI 分页并合并；脚本不会自行访问网络或补拉下一页。

维护责任归 Skill 与 Lark CLI 适配维护者。字段返回结构、类型编码、分页协议或相邻 Skill 路由发生变化时，应重跑单测、代表性只读回放和 `cases.json`。
