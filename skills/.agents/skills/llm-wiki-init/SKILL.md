# LLM Wiki 初始化

把一个空目录或现有资料目录初始化为可积累、可审计、可迁移的 LLM Wiki。核心模式参考 Karpathy 的 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：不可变 raw sources、Agent 维护的 wiki、约束 Agent 的 schema。具体实现必须与用户共同确定，不能把参考实现当成唯一答案。

## 工作姿态

- 先检查目标目录和用户已给出的信息，再提问；不要重复询问已有答案。
- 先给一套明确的推荐配置和具体例子，让用户可以直接回答“全部按推荐”。
- 把需要用户决策的内容集中为一轮设计确认；不要逐项盘问。
- 用户确认初始化配置前，不创建目录、不写契约、不安装检索工具。
- 初始化已有目录时只增量补齐；不覆盖已有文件、不移动资料、不改写原始来源，除非用户明确批准。
- 默认从最小可用闭环开始。向量库、知识图谱、自动 watcher、多 Agent 编排必须由真实需求触发。

## 默认工作流

### 1. 发现目标

1. 确认目标根目录；若用户已在目标仓库中工作，则使用当前仓库。
2. 只读检查现有的 `AGENTS.md`/`CLAUDE.md`、source/wiki 目录、README、脚本、Git 状态和已有命名约定。
3. 判断是空目录初始化、已有资料接入，还是已有知识库迁移。迁移不是默认初始化；发现会移动或重命名既有文件时，先停在设计阶段。

### 2. 完成初始化访谈

完整读取 [`references/intake.md`](references/intake.md)，根据已知信息生成一份“初始化配置草案”。

必须覆盖：

- 使用场景与主要用户
- source 的来源类型、可信度和导入方式
- source 文件命名、ID 与不可变策略
- wiki 标签命名、页面命名和语言
- `sources` 与 `wiki` 的目录层级
- 页面类型、引用粒度、状态和冲突处理
- 摄取、查询、沉淀、巡检的协作方式
- 检索脚本或外部检索工具
- 附件、隐私、版本控制和目标 Agent

向用户展示：

1. 可直接采用的推荐配置；
2. 每项至少一个贴近场景的例子；
3. 已从目标目录推断出的选择；
4. 仍需用户确认或修改的选择。

用户可以逐项修改，也可以回答“全部按推荐”。若用户已经明确说“按推荐直接创建”，视为确认，无需再追问。

### 3. 冻结设计

收到用户确认后，输出一份简短的最终配置摘要。任何会改变证据模型、现有目录或工具依赖的未决项都必须先解决；纯展示偏好可以使用推荐默认值。

根据选定检索方式完整读取 [`references/retrieval.md`](references/retrieval.md)。默认选择零第三方依赖的本地词法检索；只有出现明确规模、语义召回或既有基础设施需求时才选 qmd、现有搜索服务或自定义方案。

### 4. 创建最小闭环

完整读取 [`references/blueprint.md`](references/blueprint.md)，按确认后的配置创建或补齐仓库。

默认最小闭环包含：

- 不可变来源层、来源清单与附件目录
- Agent 可维护的 wiki 层
- 内容索引、追加式操作日志、开放问题
- 薄的根契约和按任务渐进加载的 schema
- 来源登记、pending、search/context、lint/status 的确定性工具或等价能力
- 初始化说明和最小测试

模板中的名称、目录和字段是推荐默认值，不是硬编码。用户选择不同命名时，所有契约、脚本、测试和文档必须保持一致。

### 5. 验证并交付

至少验证：

1. 空库状态命令可运行；
2. 一个临时样例来源可被登记、哈希、识别为 pending；
3. 编译出样例来源页后不再 pending；
4. 搜索能命中样例 wiki 页；
5. lint 能发现 raw source 被篡改、未知 source ID 和断链；
6. 删除临时样例后，仓库回到干净的初始化状态。

不要为了测试修改用户已有 source。优先在临时目录运行端到端测试。

最终报告只需说明：采用的配置、创建/保留的关键文件、验证结果、第一条真实来源如何加入。若某项未完成，明确写出原因和下一步。

## 核心不变量

- raw source 是证据，不是草稿区；登记后不得静默编辑、覆盖、重命名或删除。
- wiki 是可更新的知识编译层；生成页不能反过来冒充原始证据。
- 非常识性事实就近引用 raw source；来源观点、Agent 推断、用户判断和未知信息分开表达。
- 冲突、薄弱证据和未知信息不得静默合并；保留状态并进入开放问题。
- `index.md` 描述“现在有什么”；`log.md` 追加记录“发生过什么”。
- source 目录默认按稳定来源渠道分类，不按主题分类；主题交给 tags、概念页和双链。
- 优先更新已有页面，避免近义重复、低密度页面和无依据的页面扩张。
- Markdown/Git 是可移植主存储；搜索索引应可重建，不能成为唯一真相。

## 完成标准

只有当配置已确认、初始化产物已创建、最小闭环已验证、用户能看到首条来源的导入命令时，才算完成。只给目录树或只写一份长提示词不算完成。
