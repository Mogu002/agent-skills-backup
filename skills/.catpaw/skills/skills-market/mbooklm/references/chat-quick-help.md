# nb 会话快捷用法（帮助卡）

> 这是 `nb help` / `nb --help` 对应的会话式快捷参考，不含 CLI 参数细节。如需命令格式，请查阅 [cli-reference.md](cli-reference.md)。

## 第一次上手

- 已有笔记本：先说「我有哪些 nb」
- 还没有笔记本：先说「新建一个 nb 叫 项目资料」
- 想直接开始也可以：说「问 nb ...」「nb 里有哪些文档」或「把这段内容加到 nb 里」
- 如果你的目标是“把文件保存到 nb”，直接说「把这个文件存到 nb」即可
- 如果文件已经先被下载到本地，后续也应继续交给 `nb` 处理，而不是停在下载或默认转去阅读

## 高频日常说法

| 你可以说 | 效果 | 示例 |
|---|---|---|
| 我有哪些 nb | 查看笔记本列表 | 「我有哪些 nb」 |
| 新建一个 nb 叫 [笔记本名] | 创建新笔记本 | 「新建一个 nb 叫 过程管理」 |
| 在这个群里新建一个 nb / 在群里建个笔记本 | 创建笔记本；若当前在大象群上下文，会继续给当前群开通浏览权限 | 「在这个群里新建一个 nb 叫 发布知识库」 |
| 给这个群开通浏览权限 / 给当前群开通权限 | 给当前群开通笔记本浏览权限 | 「给这个群开通浏览权限」 |
| 以后就用 [笔记本名] / 切到 [笔记本名] | 设为当前笔记本 | 「以后就用 MDP」 |
| 当前笔记本是哪个 | 查询当前笔记本 | 「当前笔记本是哪个」 |
| 清空当前笔记本 / 不用 nb 了 | 清空当前笔记本 | 「清空当前笔记本」 |
| nb 里有哪些文档 | 查看当前笔记本来源 | 「nb 里有哪些文档」 |
| 搜一下 nb [关键词] | 在当前笔记本中检索相关文档 | 「搜一下 nb 发布流程」 |
| 问 nb [问题] | 向当前笔记本问答 | 「问 nb 发布流程是什么」 |
| 往 nb 加 [链接] | 导入 URL 到当前笔记本；若当前笔记本为空，会先走选择流程 | 「往 nb 加 https://km.sankuai.com/collabpage/123」 |
| 把这些加到 [笔记本名] | 导入 URL 到指定笔记本；显式指定但不存在时可自动创建 | 「把这些加到 过程管理」 |
| 把这段内容加到 [笔记本名] / 加到 nb 里 | 直接添加文本内容 | 「把下面这段加到 过程管理」 |
| 把 report.pdf 上传到 [笔记本名] / 把这个 PDF 存到 nb | 上传 PDF/Word 文件 | 「把 report.pdf 上传到 MDP」 |
| 把 notes.md 存到 [笔记本名] / 把 todo.txt 存到 nb | 保存 Markdown/TXT；必要时可按文本内容入库 | 「把 notes.md 存到 MDP」 |
| 刚才那批导入结果怎么样 / 这批链接现在哪些还在处理 | 实时查看这批来源当前状态；必须重新查询来源列表，不能直接复述上次结论 | 「刚才导入的那批链接结果怎么样」 |
| 刚才那批有几条没进来，帮我重试 / 帮我对账这批链接 | 对账本次批量导入；默认只重试失败来源，缺失链接需明确要求后再重新导入 | 「刚才那批链接有几条没进来，帮我检查并重试」 |
| 获取 [标题] 全文 / 查 [标题] 内容 | 精读某篇文档；若无上一轮检索结果，会先定位再读取 | 「获取 Spring AI Agents 接入手册 全文」 |
| 删除 [笔记本名] / 删除 nb | 删除笔记本（高风险，需确认一次） | 「删除 MDP」 |
| 更新 nb | 升级 CLI 到最新版 | 「更新 nb」 |
| nb help / nb --help | 查看这张帮助卡 | 「nb help」 |

## 当前笔记本 · 心智模型

- `nb` 默认等于「当前笔记本」
- 成功执行面向某个笔记本的查询、导入或问答后，该笔记本会自动成为当前笔记本
- 单纯查看笔记本列表不会自动设为当前笔记本
- 若当前笔记本为空，`问 nb ...` / `nb 里有哪些文档` 会先走选择流程；若仅有一个笔记本则自动采用
- 会话内有效，不跨会话持久化

## 典型链路

1. 首次使用：
   - 「问 nb 发布流程」 → 选一个笔记本 → 系统继续执行原问题
2. 文件入库：
   - 「把 report.pdf 上传到 MDP」 / 「把 notes.md 存到 MDP」
3. 先检索再精读：
   - 「搜一下 nb 发布流程」 → 「读一下这篇」 / 「获取 Spring AI Agents 接入手册 全文」
4. 批量导入后恢复：
   - 「刚才那批链接结果怎么样」 → 重新查询来源状态，不直接复述上次结论
   - 「刚才那批有几条没进来，帮我检查并重试」 → 对账本次 URL 列表，默认只重试失败来源
   - 若用户明确说「缺失的也重新导入」 → 再重新导入缺失链接
   - 结果通常会分成：已成功、处理中、解析失败、笔记本中未找到
   - 若用户说「别用缓存」「再查一次」「最新状态」，按强制实时查询处理

## 群里创建笔记本

- 如果你是在大象群里说「在这个群里建一个 nb」，系统会先创建笔记本，再给当前群默认开通**浏览权限**
- 如果创建成功但群权限开通失败，系统会明确告诉你“笔记本已创建，但群权限还没开通”
- 如果缺少当前群的 `groupId`，系统会补问
