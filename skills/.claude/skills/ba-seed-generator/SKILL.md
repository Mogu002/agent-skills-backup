# BA Seed Generator

用于在 BA 数据集场景下生成或改写种子题文件，输出目标通常是：
- `instruction.md`
- `solution/rubrics.md`

## 何时使用

当用户出现以下任一意图时，使用这个技能：
- 想基于剧本数据、预置剧本总结文件或本地底表数据生成单题或小批量 BA 种子题
- 想直接生成或改写某个题目目录下的 `instruction.md` / `solution/rubrics.md`
- 只给业务方向、剧本、难度、题型，让 agent 先构题再落盘
- 已经给出 `question` / `reference_answer`，只需要补齐本地数据文件路径并生成文件
- 在特团场景下，想优先依据 `特团MVP沙盒及剧本更新.md` 这类预置资料出题
- 在特团场景下，需要基于本地底表补证据、校对数字、确认 rubrics 是否可稳定机评

## 不适用

以下场景优先用 `ba-question-generator`，而不是这个技能：
- 需要按 L1 / L2 / L3 批量规划整套题库
- 需要先产出 Excel 题库总表或 overview/rubrics sheet
- 重点是题量分配、题型覆盖或整批题库设计，而不是单题落盘

## 默认工作姿态

无论是网约车还是特团，默认都按以下姿态工作：
- 先找**唯一且稳定的业务结论**，再反推候选题面；不要先拍脑袋写题目
- 若任务属于“先构题再落盘”，且工作区存在**题目指纹 / 防重地图**，先读取它，识别已覆盖方向与高相似题，再决定本次从哪个方向切入
- 先用**足以支撑唯一答案的最小本地证据集**；优先读取预置剧本总结与本地底表，不要为了“更全面”切去在线数据库重建题目
- 如果题面或答案里出现“达成目标”“显著”“更优”“最值得保留”这类抽象词，先补齐比较窗口、对象粒度和必要的 tie-break，再继续出题
- 若 rubrics 需要精确数值、百分比、时间点或排序结果，先从本地底表核对，再写入 `reference_answer` / `rubrics.md`
- 在口径尚未唯一化之前，不要急着落盘 `instruction.md` / `rubrics.md`
- 如果现有证据不足以支撑唯一答案，优先收窄题型、观察范围或比较粒度；不要硬写一个不可稳定机评的题目

## 默认分流路径

先判断业务域，再决定读取哪个 reference。不要默认把所有 reference 一起读完。

### 1. 先判断业务域

- 如果用户任务属于**网约车**，读取：`references/ridehailing.md`
- 如果用户任务属于**特团**，读取：`references/specialteam.md`

判断信号示例：
- **网约车**：用户提到网约车、司机、乘客、时段、订单场景、`ridehailing`、`ba-caseXX-ridehailing`
- **特团**：用户提到特团、新客、档口、入口、品类、`specialteam`、`ba-caseXX-specialteam`、`dwd_transaction` / `dws_user_daily` / `dws_stall_daily` / `dws_platform_daily`

### 2. 若是特团，先判断是否存在防重地图、预置剧本资料和本地底表

如果业务域是**特团**，优先看工作区内是否存在 `题目指纹与防重地图.md`，再看用户是否已给出预置剧本总结文件，或工作区内是否存在 `特团MVP沙盒及剧本更新.md` 与本地底表。

默认规则：
- 若存在 `题目指纹与防重地图.md`，先把它当作已有题覆盖检查的事实源；在正式构题前先识别本次不应继续走的相近方向
- 若存在预置剧本总结文件，先把它当作剧本事实源
- 若预置剧本总结不足以支撑唯一结论，或需要补精确数值 / 时间点 / 排序结果，再继续读取本地底表
- 只要本地资料已足以支撑唯一结论，就直接基于这些本地文件构造候选 `reference_answer` 与候选 `question`
- 不要为了“先理解剧本”或“补证据”切换到在线数据库 / Datasette / SQL 路径
- 防重地图只用于识别已覆盖方向与高相似坑位，不替代 `references/specialteam.md` 的构题规范

### 3. 再判断任务形态

在读完对应业务域 reference 后，再按任务形态执行：
- 用户已直接提供 `question` / `reference_answer`：直接走文件生成路径
- 用户只提供剧本方向、难度、题型要求：先走该业务域 reference 里的构题流程，再落盘
- 特团且工作区存在 `题目指纹与防重地图.md`：默认先完成一次已有题覆盖扫描，再进入候选答案 -> 候选题面
- 特团且已给预置剧本资料或本地底表：默认先基于这些本地资料完成候选答案 -> 候选题面，不把任何在线查询当成第一步或补充步骤

## 关键约束

- 不要把 `ridehailing.md` 和 `specialteam.md` 混用；两者的表结构、术语和默认题型约束不同
- 如果任务已经明确属于某个业务域，优先只读对应 reference；不要为了“更全面”同时执行两个业务域说明
- 如果特团工作区已存在 `题目指纹与防重地图.md`，在“先构题再落盘”的任务里，不要跳过已有题覆盖扫描直接写新题
- 如果特团预置剧本文件或本地底表已覆盖主线矛盾、窗口和效果，不要切去外部数据源重建剧本
- 如果 rubrics 需要精确数值、百分比、时间点或排序结果，必须先从本地底表核对，再落盘
- 如果证据不足以支撑唯一答案，先改题，不要硬写 rubrics
- 如果候选题与已有题在场景、矛盾、对象、层级、问法中重合 3 项及以上，应视为高相似题并换方向

## 跨业务域共用出题原则

以下原则对 `ridehailing` 和 `specialteam` 都成立：
- **先答案，后题面**：先写候选 `reference_answer` 的核心结论，再反推 `question`
- **优先业务判断型题干**：分析、归因、策略、经营判断类题目，优先问最终业务问题，不把题干写成教程式步骤说明
- **rubrics 锚定最终结论和关键证据**：不要只锚定中间计算量，也不要在评分时临时换口径
- **抽象词先消歧**：遇到“有效拉新”“效率不恶化”“显著”“更优”“最值得保留”等说法，先补窗口、粒度、tie-break
- **机评稳定优先**：如果不过度提示中间步骤就无法保证唯一答案，应主动收窄题型、范围或输出要求

## Rubric 与难度约束（精简版）

在生成 `solution/rubrics.md` 时，`content` 字段写的是**评分说明**，不是把参考答案原样粘进去。默认优先使用以下四种写法：
- `唯一答案：<值>`：用于 L1 精确计算题
- `答案：<值或范围>`：用于有标准答案但允许小误差的题
- `答案需提及：<要点>`：用于必须覆盖某个分析维度的题
- `答案需明确指出：<结论>`：用于必须得出某个明确判断的题

补充约束：
- 不要把 `content` 写成“识别出 XX”“能够分析 XX”这类元描述
- 不要直接把参考答案整句塞进 `content`；要写成“答案应该满足什么”的评分说明
- 如果 `content` 更像在对评分员解释，而不像在约束答案要求，说明写偏了

难度默认映射：
- **简单题 = L1（精确计算）**：核心任务是指标查询、异动识别、基期对比、ROI/LTV/CAC 这类可直接计算的问题；答案应为唯一数值或唯一枚举；instruction 必须写清计算口径；通常 1-2 条 rubric
- **中等题 = L2（结构化分析）**：核心任务是按明确框架完成分析，如漏斗拆解、维度拆解、AARRR、COHORT 等；答案可以有限开放，但必要维度应可穷举；通常 3-5 条 rubric
- **困难题 = L3（综合判断）**：核心任务是经营解读、策略建议、对标分析、AB 实验设计等综合判断；过程可以开放，但 rubric 需锚定关键洞察或决策结论；通常 4-7 条 rubric

判档边界：
- 如果题目的核心是“算出一个值 / 找到一个对象 / 给出唯一枚举”，即使需要少量解释，也优先归 **L1**
- 如果题目的核心是“按框架拆解并覆盖必要分析维度”，但不要求做最终经营决策，归 **L2**
- 如果题目的核心是“做业务判断、策略取舍、方案设计或优先级决策”，即使中间需要框架拆解，也归 **L3**
- 用户说“简单 / 中等 / 困难”时，默认分别映射为 `L1 / L2 / L3`
- 若用户要求的难度与当前证据强度不匹配，优先降级到能稳定机评的层级：`L3 -> L2 -> L1`；不要为了迎合难度硬造不可判题目

## 最小工作流

1. 识别业务域：网约车或特团
2. 只读取对应 reference：`references/ridehailing.md` 或 `references/specialteam.md`
3. 若是特团且工作区存在 `题目指纹与防重地图.md`，先完成一次已有题覆盖扫描，明确本次不应继续走的相近方向
4. 若是特团，先读取预置剧本总结文件；若证据不足或需要精确数值，再继续读取本地底表
5. 若用户未给现成题面 / 答案，先完成防重扫描 -> 本地剧本 / 底表分析 -> 候选答案 -> 候选题面
6. 补齐本地数据文件路径并生成或改写 `instruction.md` 与 `solution/rubrics.md`
7. 落盘前再做一次唯一性检查；若无法稳定机评，先收窄题型或口径
