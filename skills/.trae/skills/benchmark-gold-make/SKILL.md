# benchmark-gold-make

对 benchmark 评测主控表里的每一行题目，把【指令】当成真实用户 query，在该题【考察数据表的副本】所指的若干目标 Base 上**真正执行检索**（含打开 PDF/图片核对、跨表语义 Join），据此产出标准答案并回填三个字段：**【参考答案】【目标表】【命中附件】**。

核心立场：**答案只能来自目标 Base 的真实数据与附件内容**。【样张设计思路】【考察点】只用于理解语义键与正负样本，**不得当作答案依据**；真实数据与设计不符时，以真实数据为准，宁可少报不凑数。

## 适用判断

先确认任务是"执行 query 产出 gold / 回填参考答案 / 回贴命中附件"。如果是构建样张数据 → `benchmark-base-make`；核验副本是否实现设计意图 → `benchmark-sample-verify`；按检查备注修样张 → `base-sample-fixer`。本 skill 只做"读 + 答 + 回填"，默认不改目标 Base 的数据。

## 前置：对齐，不要默认

开工前与用户确认（除非用户已明确）：

1. **做哪些行/题号**，一行一题、无状态、禁止跨题复用结论。
2. **要填哪些字段**，字段中文名以主控表实际 schema 为准（常见：参考答案 / 目标表 / 命中附件；也可能是机评、检查结果等——先 `+url-resolve` 读 schema 不要猜）。
3. **是否真的写回表**。写回是不可逆外发动作，先与用户对齐再执行。
4. 当**真实数据无法支撑 query**（跨表 Join 近乎 0 命中、附件失效、设计与数据冲突）时的处理口径：如实少报 / 先出诊断 / 放宽匹配——让用户拍板，不要自行放宽。
5. **PDF 核对深度**：只对真实命中项读 PDF（推荐） / 全量读 / 不读仅看元数据。

## 执行流程（每行重复，无状态）

1. **解析主控表**：`lark-cli base +url-resolve --url '<带 table、view 的链接>' --as user` 取 base_token / table_id，并从返回的 fields 读全字段 schema（类型、select 选项）。
2. **读目标行**：用 `+record-list --filter-json @file.json` 按题号精确取行（PowerShell 下 `--filter-json` 必须用 `@相对路径文件`，见 references）。拿到【指令】【考察数据表的副本】【考察数据表名】【样张设计思路】【考察点】。
3. **解析副本 Base**：对【考察数据表的副本】里每个链接 `+url-resolve` → base_token；`+table-list` 看表名/行数，`+field-list` 看字段 schema。**先核对真实 schema/行数与设计思路是否一致**，差异要记下并以真实为准。
4. **判定数据可用性**：先用结构化字段 + 附件文件名做"能否命中"的快速评估（文件名常带政策标题/指标/公司名）。识别数据是"真实爬取"还是"按考点构造的合成样张"（合成样张常有 `-pos-/-neg-/-fill-` 前缀、页脚标注"合成评测样张"）——合成正样本才是真正的可命中集合。详见 [references/grounding.md](references/grounding.md)。
5. **执行 query**：按【指令】要求的输出列与筛选/匹配规则检索。凡要求"打开 PDF 封面/正文、图片核对"处，必须真正读取附件内容（真实 PDF 走文本层抽取 `scripts/pdf_text.py`；扫描件/图片走视觉或 OCR）。跨表 Join 按 query 指定的语义键（公司全称 / 行业主题 / 指标口径）匹配，并应用状态/类型/有效性/口径一致性等过滤。
6. **组织三字段值**（见下）。
7. **回填**：目标表 + 参考答案用 `+record-batch-update --json @file`；命中附件先 `+record-download-attachment` 再 `+record-upload-attachment`。命令配方见 [references/lark-cli-recipes.md](references/lark-cli-recipes.md)。
8. **读回验收**：`+record-get` 投影这三个字段确认写入成功。

## 三字段填写规范

### 【目标表】（多选 select）
- 取本行【考察数据表名】按「、」拆分的每个表名逐一选中。
- 选项名必须与字段已有选项**精确一致**；不存在就不要新建选项，记为异常待确认。

### 【参考答案】（文本，即 gold）
- 严格按【指令】要求的输出结构作答（query 要"公司全称 | 年报编号 | 招股书编号 | 关联公文文号"就按此列输出对照表），中文。
- **三类信息分开表达**：已核验事实（来自附件实际内容）/ 推断匹配（靠名称、行业、口径语义对齐，须显式标注"推断"）/ 存疑未命中。
- **接地**：每条结论可回溯到目标 Base 的具体记录或附件内容（给出文号/编号/文件名/指标值等锚点）。
- **诚实约束**：不臆造。附件打不开/失效(404)/内容与 query 前提矛盾，就在该条注明"附件不可访问/内容不符，未能核验"。宁可少报不凑数；全无命中就如实写"无合规命中，对照表为空"并给依据。
- 可附一段【数据与设计差异】说明（供参考、非答案依据），点明真实数据与设计思路不符之处。

### 【命中附件】（附件）
- 只贴**真正打开并作为核对依据**的附件（被匹配公司的年报/招股书 PDF、被筛中的红头公文、被引用的统计公报/图表等），不要把目标表所有附件全贴。
- 从来源 Base 对应记录下载后上传到本字段；**保留来源原文件名**以便追溯。
- 失效文件不贴占位，在参考答案对应条目注明即可。单元格最多 50 个附件、单文件最大 2GB（>20MB 自动分片）。

## 全局约束

- 一行一题、无状态；只写被指定的目标字段，不动其他字段、不改目标 Base 数据。
- 保持独立判断，**不迎合【样张设计思路】的预设结论**（反顺从）。
- 任一目标 Base 无法访问时，在参考答案注明"未能核验"并跳过其命中附件。
- 中间产物（下载的附件、抽取文本、payload JSON）放在工作目录的临时子目录，别污染交付目录。

## 常见陷阱

- 真实数据与设计思路系统性不符（行数、字段名、主体、正样本都对不上）→ 以真实为准，别照搬设计编答案。
- 跨表 Join 用"同名"要分清口径：指标同名但统计口径不一致（如政策"五年累计降幅" vs 统计"当年同比降幅"）属硬负样本，不能计入命中。
- "伪扫描件"：PDF 自称扫描件但有完整文字层（ReportLab 生成、含 /Font 与 BT/ET）→ 可直接抽文本，不必依赖 OCR；判定方法见 references。
- PowerShell + lark-cli：`--filter-json` / `--json` / `--output` 都要求**相对路径的 @file**，直接传长 JSON 字符串会被 shell 拆坏；见 recipes。
- 本机工作目录可能有 `inspect.py` 等文件污染 Python stdlib → 用 `scripts/pdf_text.py`（已在运行时剔除 cwd/'' 出 sys.path）或换 cwd 运行。
