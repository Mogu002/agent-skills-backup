# Dashboard Eval Annotator

这个技能用于按 Dashboard Agent 评测手册给「仪表盘产物 / AI 回复」打分并写标注。
核心目标不是判断仪表盘做得好不好看，而是：**比照用户 Query 里的全部显性要求，按二分制判定该条数据是否通过，0 分项逐条记录错误并打错误标签。**

## First Principles

每次打分前先固定四件事：

- **比照对象是 Query**：阅读并对齐 Query 里的全部用户要求，逐条核对，不靠主观印象。
- **二分制 + 一票否决**：默认 0/1 打分；**任一项出错即判该条「未通过」得 0 分**，不叠加扣分。
- **0 分必须逐条记录**：在备注里写清每一处「有差异 / 错误 / 不达成」的情况，并勾选对应错误标签。
- **延展默认宽松，偏离默认扣分**：合理延伸组件 / 筛选条件算对；偏离场景、误解、遗漏 Query 信息算错。

只评产物与 AI 回复，不替模型补做仪表盘，也不给 Query 补隐性需求。

## 评分制（先记住）

| 场景 | 给分 |
|-|-|
| 完全满足 Query 全部要求 | **1** |
| 任一项出错（理解 / 执行 / 配置 / 排版 / 遗漏） | **0**（一票否决） |
| **指令没执行完** 或 **没出现仪表盘** | **-1**（仅 direct） |

> reflect 各子类统一按 0/1；direct 额外有 -1 两种情形。二轮只评 1 分项、与一轮人员不重复。

## Triage：先判断这是哪类评测

| 信号 | 路径 | 读哪个文件 |
|-|-|-|
| BWE-Direct 评测集；对照原始 base 和答案，逐组件核对配置 | **direct** | [`references/direct-scoring.md`](references/direct-scoring.md) |
| BWE-Reflect 评测集；任务类型为「推理 / 共创 / 澄清 / 用户意图优先」，需在侧边栏交互后评测 | **reflect** | [`references/reflect-scoring.md`](references/reflect-scoring.md) |
| 任务类型为「拒识」 | **不评**（产研内部评测），直接跳过 | — |

不确定时默认走 direct 的判分标准（reflect 的「合理推理&多轮协作」本身也复用 direct 标准）。

## Default Workflow

1. 用 triage 判断 direct / reflect / 拒识(跳过)，读取对应 reference。
2. 从 Query 拆出显性要求清单（对象、字段、指标、筛选条件、分区/部分、数量、布局要求等）。
3. 逐组件点开查看配置（数据源、字段、横轴、筛选条件等），**不要改动原配置**。
4. 对照[四个判分维度](references/direct-scoring.md)和[例外情况](references/direct-scoring.md)逐条核对；命中任一错误即 0 分。
5. 截图（不带头部和侧边栏，长图滚动截屏）。
6. 给分；0 分项勾选错误标签并在备注逐条记录；按需补充特殊标签（合理延伸 / 系统限制豁免 / 底表能力不足 / 需重评 / 可优化）。

## Key Gotchas（最容易判错的地方）

- **布局只在特定场景查**：仅「0-1 构建」或「要求全部重新排版」时检查紧密布局；已有仪表盘新增组件、未要求美化时，排版混乱**不算错**。
- **系统不支持 ≠ 错误**：图表选项、自定义配置、组合图左右轴/形状、文本/标题样式、表格前 X 名展示等系统不支持的配置，只要核心功能达标就算对。
- **底表能力不足是 Query 问题**：底表算不出 Query 要的指标（如逾期客户数）时标「需修改 Query」，**不判执行者错**。
- **时区偏差算对**：服务器时区导致的时间显示偏差判正确。
- **时间筛选要算清边界**：如「二月」应为 ≥2/1 且 <3/1，而非 >1/31 且 <2/28。
- **拒识类不评**：交给产研内部，别打分。
