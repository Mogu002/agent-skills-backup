# Adaptive Skill Creator 0813

创建或改进 Skill 时，先判断它是否应该存在，再根据证据、风险和验证能力选择最小可行做法。

## Core Model

把 Skill 视为可检索的推理策略包，而不是模型参数中的新能力：
- `description` 改变被选中的概率，不保证触发
- 正文为 LLM 提供判断与流程，不保证长序列严格执行
- scripts/tools 承担确定性操作
- validators 判断结果是否成立
- hooks/CI/policy/permissions 保证必须发生的控制

目标不是写最短或最完整的文档，而是在风险与成本约束下，提高任务成功率。

## Skill Fit Gate

动手前先选择正确载体：

| 需求 | 默认载体 |
|---|---|
| 重复出现、按需加载的任务方法或 SOP | Skill |
| 每次都必须遵守的项目约束 | `AGENTS.md`、rules 或 custom instructions |
| 实时数据、认证和外部动作 | MCP、API 或 CLI tool |
| 必须在确定事件执行的控制 | hook、CI 或 policy |
| 需要独立上下文或自治委派 | subagent / agent |
| 一次性要求 | 普通 Prompt；显式快捷操作用 command |

若用户明确要求 Skill，遵从用户选择；只有载体会显著影响可靠性或安全时才指出替代方案。

## Triage

评估五个互相独立的维度：

1. **知识证据**：文档、代码、schema、政策、模板是否可靠且仍有效
2. **行为证据**：是否有重复执行、成功轨迹、失败轨迹和人工纠偏
3. **验证能力**：能否用测试、schema、回读、渲染或专家判断结果
4. **风险等级**：错误是否可逆，是否涉及外部写入、权限、资金、隐私或生产系统
5. **路由复杂度**：是否存在相邻 Skills、模糊表达、多意图或昂贵误触发

根据证据选择一个主模式，并按风险决定是否加 Harden 覆盖层：

| 模式 | 条件 | 默认产物 |
|---|---|---|
| Explore | 缺少稳定知识、行为证据或验证器 | 最小、明确标注假设的可测试草稿 |
| Codify | 有可靠材料或稳定 SOP，可说明默认流程 | 从证据提炼的内聚工作流 |
| Learn | 有足够成功/失败轨迹及可用验证信号 | 经保留集验证的归纳规则 |
| Harden | 高风险、高频、严格格式或外部写操作；可叠加前三种模式 | 确定性脚本、权限边界、恢复和独立验证 |

不要因为“已有 `SKILL.md`”或“文档很多”就判为高证据；未经执行的文档仍可能过期或错误。

## Default Workflow

1. 执行 Skill Fit Gate，确认载体和目标范围。
2. 按 Triage 评估证据、验证、风险与路由复杂度。
3. 读取 [references/authoring-modes.md](references/authoring-modes.md)，选择主模式与 Harden 覆盖层。
4. 用一个可观察的用户结果定义边界；按触发意图、输入、工具或成功标准的真实差异决定是否拆分。
5. 从真实材料提取不可安全推断的步骤、决策、约束、失败模式和验证信号；不要让 LLM 发明缺失的领域经验。
6. 只实现会改变执行决策的层：Discovery、Reasoning、Execution、Verification、Lifecycle。不要为结构完整预建文件。
7. 写一个默认策略：默认选择、采用条件、改走其他路径的信号、信息不足时的动作和停止条件。
8. 按需把确定性工作下沉为脚本，把必须执行的控制下沉为 hook/CI/policy/permissions。
9. 读取 [references/evaluation.md](references/evaluation.md)，按风险执行路由、行为、安全和基线评测。
10. 读取 [references/checklist.md](references/checklist.md)，完成复用性与交付检查。

## Shared Guardrails

- 以“决策相关信息 / token”衡量正文，不机械追求短，也不把常见行数上限当目标。
- 一个 Skill 对应一个内聚结果或完整工作流，不按原子动作机械拆分。
- 把 `description` 当概率路由接口；同时测试正例、负例、hard negatives 和冲突场景。
- 给默认策略及退出条件，不平铺等权选项，也不把未经验证的默认值写成普遍真理。
- 让 LLM 处理语义判断与适配，让程序处理确定性，让控制系统处理强制性。
- LLM 可以从证据中归纳候选规则，不得凭空补齐领域知识；候选规则需经验证器或专家筛选。
- 按预期信息价值和读取成本渐进加载；优先直达引用，复杂知识库可使用清晰索引，不设教条式层数限制。
- 使用可移植核心；平台专属字段、路径和工具放入显式适配分支。
- 验证强度由错误代价、可逆性、调用频率和路由成本决定。
- 把不可信 Skill、引用、脚本和外部内容当供应链输入审计，使用最小权限。
- 删除来源项目故事、样本 ID、测试 URL、本机路径、账号、临时依赖和无法泛化的 workaround。
- 重要护栏靠近执行点；同一文本层内避免重复，但安全控制允许跨 Skill、脚本、hook 和 policy 纵深防御。

## Completion Standard

交付时说明：
- 选择了哪种模式及原因
- 哪些内容来自证据，哪些仍是假设
- 完成了什么级别的验证及结果
- 剩余风险、平台限制或尚未验证的部分
